# Coptic HTR Pipeline

## Status: Working, High Variance

This pipeline uses Claude Opus 4.7 as a vision model to transcribe Coptic manuscript photographs. It works, but results vary significantly between runs due to model non-determinism. Typical performance: **5-10% CER** (spaceless metric), with occasional runs as low as ~1.5% or as high as ~15%.

Word accuracy is more stable: **85-90%** across runs.

## Pipeline

### 1. Preprocess: Cut out the papyrus

```bash
python scripts/preprocess_page.py data/claremont/codex_ii_page_35_full.jpg
```

This does exactly three things:
1. Threshold (brightness > 80) to separate paper from black background
2. Find the largest contour (= the paper)
3. Crop to its bounding box and scale to target height

Output: `<name>_preprocessed.jpg`

### 2. Transcribe: Send to Opus 4.7

```bash
python scripts/test_papyrus_htr.py --image data/claremont/codex_ii_page_35_full_preprocessed.jpg --prompt-version 6 --effort xhigh
```

Best settings established:
- **Prompt version 6**: Paleographer persona, one-line-per-output-line instruction
- **Effort xhigh**: Maximum adaptive thinking
- **Whole page**: Do NOT segment into lines (proven worse)
- **No English context**: Do NOT provide translations (proven worse)
- **No grid overlay**: Do NOT add coordinate grids (proven worse)

Output: `temp/htr_v6_effort_xhigh_folio_35.json`

## What Didn't Work

| Approach | Result | Why |
|----------|--------|-----|
| Per-line transcription | ~10% CER | Model loses page context |
| Grid watermark overlay | ~9.5% CER | Visual noise |
| English translation as context | ~6% CER | Model reconstructs instead of reading |
| Line segmentation + context image | ~6% CER | Still worse than whole page |

## Metrics

- **CER (spaceless)**: Edit distance after stripping spaces, editorial marks (hyphens, apostrophes, brackets), and combining marks (overlines). This compares only base Coptic characters.
- **Word accuracy**: Percentage of words matching after normalization.
- **Exact line matches**: Lines with zero errors after normalization.

## Ground Truth

Folio 35 of Codex II (Gospel of Thomas, Sayings 13-16). 36 lines, 928 base characters. Ground truth from Linssen's critical edition via PyMuPDF extraction.

## Source Images

### Provenance

Manuscript photographs are from the **Claremont Colleges Digital Library**:
- Collection: "Nag Hammadi Codex II" (digital facsimile)
- Source URL: `https://ccdl.claremont.edu/digital/collection/cce/id/2046` (Codex II, page 35)
- Download: JPEG2000 master via IIIF (`/full/full/0/default.jp2`)

### Reproducing

```bash
# 1. Download the original JP2 (only needed once)
#    Already in data/claremont/codex_ii_page_35_original.jp2

# 2. Convert JP2 to JPEG for tooling (ImageMagick or similar)
magick convert data/claremont/codex_ii_page_35_original.jp2 data/claremont/codex_ii_page_35_full.jpg

# 3. Cut out the papyrus
python scripts/preprocess_page.py data/claremont/codex_ii_page_35_full.jpg

# 4. Run HTR
python scripts/test_papyrus_htr.py --image data/claremont/codex_ii_page_35_full_preprocessed.jpg --prompt-version 6 --effort xhigh
```

### Files in `data/claremont/`

| File | Description |
|------|-------------|
| `codex_ii_page_35_original.jp2` | Original JPEG2000 master from Claremont (22 MB, 6000×8400) |
| `codex_ii_page_35_full.jpg` | JPEG conversion of the above (4.6 MB, same dimensions) |

All other images (preprocessed, cropped, etc.) are generated by the pipeline and not committed.

## Scripts

| Script | Purpose |
|--------|---------|
| `preprocess_page.py` | Cut papyrus from photograph |
| `test_papyrus_htr.py` | Send image to Opus 4.7, compare against GT |
| `segment_lines.py` | Line segmentation (kept for reference, not used in optimal pipeline) |
| `extract_coptic_pymupdf.py` | Extract Coptic text from Linssen PDF |
| `extract_tractates.py` | Extract English translations from Robinson PDF |
| `mirror_to_drive.py` | Sync tractates to Google Drive as styled PDFs |

## Known Limitations

1. **High variance**: Same image + same prompt can give 2-15% CER depending on the run. No way to control this with current API.
2. **Overline sensitivity**: The model inconsistently applies combining overlines (̅) which inflates raw CER. The spaceless metric handles this.
3. **Line breaks**: Model occasionally merges or splits lines differently from the manuscript, which cascades errors in line-by-line comparison.
4. **Cost**: Each xhigh-effort run uses ~5k input + ~10-20k output tokens on Opus 4.7.
